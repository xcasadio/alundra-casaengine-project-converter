# dll-structure

Tooling of the restructuring of the Alundra gameplay DLL (`docs/plan-restructuration-dll.md`, ADR-0075). Python 3, standard library only,
always run with `python -B`. Read-only on the repository except the scripts that write: `gen_table.py` (writes `table.json` and `table.md`), `apply_r2.py`, `apply_r4.py`, `apply_r5.py` and `apply_r6.py` (the working tree of their slice) and `gen_extra_types.py` (writes `rules-extra-types.tsv`).

**Since R7 the guard is `check_names.py --rules`** (below): it needs no table and is the command that "the collision check green" means in the plans. The table-bound modes (`--table`, `--tree`, `--tests`), `selftest.py` and the proofs `prove_r2.py` to `prove_r5.py` are the **archive of the chantier**.

| Script | Role |
|---|---|

| `gen_table.py` | Generates `table.json` and `table.md`: for every top-level type of the DLL at the pinned revision `BASE_REVISION`, its file, namespace and name at stages `r2` (moved and split, no rename), `r3` (renamed) and `final` (after the nine data-cited types move in R4). Replayed, it gives the same bytes (`git diff --exit-code tools/dll-structure`). It fails if a file is unmapped, a file has no known main type, two split types aim at one path, or a name occurs twice in a namespace (a partial type excepted). |
| `check_names.py --table` | The planned names against the engine, MGUI, NvgSharp, packages and BCL: type collisions, namespace segments that would mask a type, a type named like a segment of the DLL. Lists every finding; exit 1 if any. |
| `check_names.py --tree --stage r2\|r3\|final [--root <folder>]` | The tree of the DLL (working tree, or `<folder>/Alundra`) against the table at that stage: absent file, `.cs` outside the table, type missing under its name, in another namespace or file; then the collision checks on the names really declared. Lists every deviation; exit 1 if any. |
| `selftest.py <work folder outside the repository>` | Builds synthetic trees from the table and proves the checks fire: conforming tree, wrong namespace, wrong name, extra file, missing file, and a final name changed to `Vector2` (`--table`). |

## Frozen proofs (after R5)

R5 moved and renamed the files of `Alundra.Tests/` (every `.cs`, every test class), and the end-of-tranche proofs of R3 and R4 read paths of that folder
(`r3-literals.tsv`, `r4-literals.tsv`). They are therefore **frozen at the commit of their tranche**: `r3_literals.py check --stage after`,
`prove_r3.py --all` and `prove_r4.py --kind end` only replay at `a193671` (end of R3) and `ce6d335` (end of R4); on a later tree they would read paths that no
longer exist, and nothing in those tables is remapped. From R5 on, the tests tree is checked by `check_names.py --tests` and `prove_r5.py`.

From R7 on, the whole archive is frozen: `--table`, `--tree`, `--tests`, `selftest.py` and `prove_r2.py` to `prove_r5.py` read tables (`table.json`, `r5-files.tsv`,
`r5-types.tsv`) that describe the tree as the chantier left it, so they refuse every file added or renamed afterwards (`[hors table]`). They replay at their
closing commits, not on the living tree; `check_names.py --rules` is the check that lives on.

R6's own proof is frozen at its closing commit `2964d9ae`, like those of R3 and R4: `apply_r6.py --check` and `r6-occurrences.tsv` describe the occurrences
of the old names as R6 left them (the paths of the DLL as of R3, the lines of the documents as of R6) and already refuse the tree of today (3 011 files
modified since `211a757` outside their scope). The line numbers that the living documents cite are not guarded: they wear out with E14, E19 and E20
(P-R6b-5). `prove_r6b.py` replays the R6b tranche (the 21 living documents against `r6b-citations.tsv` at the pinned trees of `33528d55`), not the later states.

## Where the data comes from

- DLL files for the table: `git ls-tree` at `BASE_REVISION` (the parent HEAD at the end of R0, `5434cf6`), so the table does not move when R2 to R4
  move the files. DLL files for `--tree`: `git ls-files --cached --others --exclude-standard -- Alundra` (no `bin/`, `obj/`, `artifacts/`) read in the
  working tree, or every `.cs` under `<root>/Alundra` when `--root` is given.
- Engine, MGUI, NvgSharp: the HEAD of their submodule (the author's uncommitted changes there are not read).
- Packages and BCL: the XML documentation files (`~/.nuget/packages`, `Microsoft.NETCore.App.Ref` 9.0). The list of packages is in
  `scan_types.PACKAGES`; a listed package whose XML is not found is an **error**.

## Limits

- Declarations are read by a regular-expression reader, not a compiler; nested types are ignored by the name checks (they never collide with an
  imported name), except that `check_names.py --tests` flags a nested type that keeps the `Alundra` prefix.
- `Portable.Xaml` ships no XML documentation (`scan_types.PACKAGES_WITHOUT_XML`, named explicitly): its types are not checked by the script. A
  clash there would be an ambiguous reference (`CS0104`) and the build is the judge.
- `--rules` limits: a type declaration that does not start its line is invisible to the reader, so it is reported as `[lecture]` rather than read; the collisions of nested types and the member names (for example the test methods `AlundraSoundBank_GetOrCreate_...`) are not checked; the existence of the nine types that the data cites, `tools/AlundraTestSaves/` and the files that are not `.cs` (for example under `Alundra.Tests/Data/`) are outside the guard; a new folder is allowed (there is no closed list of domains); `rules-extra-types.tsv` is a snapshot of the packages at the time it was generated and is not refreshed by itself; `Portable.Xaml`, `StbImageSharp` and `StbTrueTypeSharp` stay unread (the build judges), and so do 3 BCL types that have no XML documentation (none is in the implicit usings of the tests).
- Warnings, not failures: a type nested in `Alundra.Tests` named like a namespace segment (today `Session` in `TextBoxGpuHarness.cs`) only masks the
  segment inside its own class body.
