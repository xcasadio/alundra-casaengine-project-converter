## 0. Conventions

- Units 16.16 (1 px = 65536). `PosZ_bin` is what the binary stores; `PosZ_dll = PosZ_bin - 1` (ADR-0026); heights `h` are `(PosZ_dll - TerrainHeight) / 65536` px.
- **Update k** is the physics pass `P` (0x80038364) of the tick **s+k-1**, where s is the tick of the `1A` / `1B` instruction: in one tick the binary runs the scripts (0x800386D0), the lists (0x800384F4), UpdateAnimation (0x80038E18), then P (order of UpdateEntities 0x8003B388). Update 1 is the pass that applies the impulse or the force.
- `0x25` (handler 0x8003DB7C) returns 1 when `+0x140` (contact, `CollidedWithEntityZ`) or `+0x144` (`IsOnGround`) of the logic entity is non zero; it reads the pass BEFORE the tick of the script, so a condition that appears at update K makes it return at tick **s+K**.
- Before the program starts, 3 passes without script settle the rest state (the DLL tests do one `calage` update). Gravity entities at rest show contact 1 and FinalForceZ -32768 at every tick.
- Two engines: A = zsim (mips.py, python RunScript loop), B = vz (emu.py core, REAL RunScript 0x8004205C); two rules models: zmodel.py (+ zmodel_dll.py, binary - 1) and `M` of rules_vs_emu.py. In every case below A, B and the models agree on PosZ, ForceZ, FinalForceZ, contact, IsOnGround of every update (column `agree`).
- UpdateAnimation is NOT executed: the stand-in is run_ticks.py `anim_A` (Current = Target; `+0xF8` = IZF of the animation at a change, else 0). It is valid for ONE animation change per jump.
