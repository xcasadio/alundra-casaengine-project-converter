## 3. Corrections to the report

- C1 (R-draw): the bucket is the arithmetic shift of the key, `16*min(key>>20, 59)+6` with `>>` signed; a key >= 0x80000000 is a NEGATIVE slot in the binary (undefined behaviour), not slot 950. State "keys are always >= 0 in the corpus; clamp at 0".
- C2 (D-E19-54 / Q-1): scripts reach native effect creators through TWO opcodes, not one: `0x82` (sub-cases 0x50-0x56, only 0x53 used, 8 sites) and `0xBB` (retry/game-over, maps 347 and 477, E18; calls `RestoreHpAndMpAndCreateEffect`). The three other script handlers that reach a creator are `0x90`, `0xA2`, `0xA3` (SpawnMapEffect). No other handler of the table reaches a creator through direct calls (indirect jump tables not followed).
- C3 (modes): every effect a script or a record can create is mode 0 (`SpawnMapEffect` passes mode 0, `CreateEffectEntity` is mode 0; mode 2 has no caller; modes 1/3 come only from 5+1 native sites: player weapon, balance records, DestroyEntity). G3 needs the mode-0 pool only; modes 1-3 (entity-attached) belong to E14. The report's R-modes should be marked "E14".
- C4 (G2b independence): map 10's chain scene also spawns record 1 (global effect 12, 7/9 deformed, 2 sites `0x90`) and record 2 (global effect 3, 145/184 deformed, 1 site `0x90`); 135's `0xA3 [1]` is global 13 (27/29 deformed). So "10 and the 135 altar can ship before G2b" holds for their MAP effects only; the maps with ALL their effects rect_src are 391, 163, 162/169/176/183/478 (Inoa). Maps 165/172/179 (chain neighbours, no row in the closed list) each have `0x90 [0]` + `0x93` on global effect 14 (156/204 deformed): script sites the chain audit does not reach.
- C5 (G1 file layout): 623 distinct signatures across the 87 effect sheets, 203 of them shared by more than one sheet (up to 28 sheets). The `.sprite` files are named `sprite_<signature>.sprite`: they must live in a per-sheet (per-map) folder, otherwise files collide although the ids differ. Mirrored rect_src refs (1 719) carry the +1 source shift of `SiImage.ShiftSource` in their signature.
- C6 (G3a ambient spawn): the hero tile at load is the hero's start tile (established, claim 28); spawn order after the entity init.
- C7 (G3a gate): the effect pass must not sit behind the proxy's `PlayerEntity == null || tickBlocked` early `continue` (`AlundraWorldProxy.cs` ~2261-2266): the binary ticks effects every tick (frozen only by 0x48), hero or not.
- C8 (A1/A3 first match): 396 of 438 `0xA3` sites use search key 0x81 (the hero), 16 use 0x80 (self), only 29 A1/A3 sites (26 + 3) use a sprite-table-index search where "first match" depends on the binary's entity order; chain: one `0xA3` (135, key 0x80).
- C9 (tests): add `AlundraEventProgramRunnerTests.UnknownOpcode_KnownSize_SkipsBySize` (uses 0x93).

## 4. What would change the plan

1. Q-1 stands, with C2: D-E19-54 (warp = map transition effects) is a misreading; native creator API for G3c = `0x82 0x53` only, `0xBB` goes with E18.
2. G3a can be split smaller: mode-0 pool + load spawn + tick + push (no entity attachment, no native creators).
3. G1 must specify per-sheet sprite folders (C5) and the padding/terminator conventions of the JSON (claim 10).
4. G3b removes the 99 rows, and the unit test in C9.
5. The report's slice order is otherwise sound: rect_src scenes (391, 163, Inoa, 10 rock/altar) first, 476 + global deformed effects after G2b.
