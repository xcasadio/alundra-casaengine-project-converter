## The open question (sampling): numbers confirmed, framing corrected

- Numbers CONFIRMED with independent code (`sampling.py`): 40 763 scaled refs; 40 126 (98.4 %) differ on at least one texel row or column between GPU pixel-centre sampling and integer-position sampling; 2 691 refs under integer-position sampling read a texel outside the crop (the crop reads inside in 100 % of cases under centre sampling).
- **Missed, decision-relevant (fact, ADR-0048 + `alundra-project/AlundraGame.json:11` + `ProjectWriter.cs:79-83`):** the project declares a virtual resolution (IntegerFit); the view is rendered "straight into the letterboxed back-buffer viewport; no intermediate render target", with camera `Zoom = k`. At k > 1 the GPU samples one texel per SCREEN pixel, k*k samples per PS1 pixel. For a scaled quad, the engine output at k = 4 differs from the PS1 result (either convention, each enlarged by k) on 99.2 % / 99.1 % of the 40 763 refs (`sampling_k.py`). So at the normal play sizes neither convention reproduces the PS1 per-PS1-pixel texel selection; only k = 1 can. The 1:1 classes (plain, mirror) stay exact at any k. Consequence for the plan: the choice "(C) now, (H) later" is not a quality knob for hardware-exact scaled quads; hardware-exact scaled quads need the sprite pass rendered at the virtual resolution into a render target (deferred in ADR-0048), not "a half-pixel UV shift plus an extra atlas column". The honest contract is "deformed/scaled quads are resampled at the output resolution; exact only at k = 1 and for 1:1 classes", documented as a measured delta.
- Supporting evidence the report presents only as "usual emulator practice" (H): the extractor's own finding in `SiImage.cs:30-46` (177 564 of 208 830 mirrored quads have an unmirrored twin stored at exactly Sx+1, "because the GPU walks the texels backwards from the far edge") is consistent with integer-position sampling and not with centre sampling (under centre sampling a 1:1 mirrored quad would read the same window as the unmirrored one and no shift would exist). So H is supported by in-repo data, still not by documentation (psx-spx fetched again: split documented, evaluation position not documented).
- Additional measured subset (H model, `rot90.py`): 751 deformed refs are quarter turns (u along screen Y, `X1==X2`, `Y1==Y3`), all of them also scaled (no 1:1 quarter turn exists). The extractor chooses `SourceX/SourceY` from `X1>X2` / `Y1>Y3` only, so for these refs the crop window can be one texel off the window the PS1 reads (e.g. reads columns 1..8 of w = 8 while the crop is 0..7). Inside the same "not exact for scaled/rotated quads" delta; no action beyond documenting it.

## Corrections and additions that would change the plan

1. Replace "12 870 would be culled" by "9 610 (negative signed area)", and add the zero-bow-tie measurement; consider "swap slots 1 and 3 by orientation" as the primary no-state solution, NoCull as fallback or for the API contract (a quad whose triangles disagree is unsupported or needs NoCull; none exist in 160 355 entity refs or in the effect quads).
2. Parent ADR number: not 0039 (taken by f4a's plan); use 0040 or later and re-check.
3. Sequence and baseline: E19.f4a changes `SpriteWriter.cs` (new pass after the bank loop, `Data/sprite-records.json`, `.sprite` files under `UI/Portraits/`, `Assets.Sprite`, catalog). The "exactly 1 923 `.anim2d` + `report.json`, `AssetInfos.json` and `sprite-records.json` unchanged" acceptance must be measured against the post-f4a export, and G2b's `ConvertAnimation` edit should land after f4a to avoid a conflict in the same file.
4. Sampler: `ApplyTrack` has `default: throw` (`Animation2dCompositionSampler.cs:269`); an engine without the `Corners` case would throw at the first sample even if the load somehow succeeded. Add to the "lock-step" argument and to the red test.
5. `AnimatedSpriteComponent`: mark `IsBoundingBoxDirty` when the corner state changes (not only when the first visible sprite changes) and feed the corners to `Animation2dBoundsCalculator`.
6. The `zOrder` path is also the one the editor preview takes (a preview component has no `DepthSortable2DComponent`): another reason to give it the quad path (the report's recommendation "yes" stands).
7. Demo table: print the texel-boundary margin (>= 0.06 texel) rather than "px from the diagonal".
8. Add to the risk list: G1/G3 will reuse the quad entry; effect quads include 52 zero-area quads and 3 170 parallelograms (rotations); they pose no new cull problem under the orientation rule.
