## B. Refuted or corrected

### B1. The "PSX rule" `floor(i * src / dst)` [hyp] is the superseded floor model; the repository already holds the hardware-verified rule (substantive)

- `docs/plan-e19-g2b-annexe/data-verify.md` section C1 (PCSX-Redux hardware-verified, 30/30 and 19/19 probes) and the plan's "Règle de texel corrigée" (`docs/plan-e19-opcodes.md` ~7855): the PS1 reads the texel `floor(u + 0.5)` at the integer pixel; the "floor" model was explicitly refuted there.
- For an axis-aligned quad of size d showing s texels: PS1 `floor(i * s / d + 0.5)` (ties up), GPU centre rule `floor((i + 0.5) * s / d)`.
- [calc] `v9.py`, the 25 sprites of UI/Portraits x 14 flight sizes, 350 frames, share of destination pixels whose colour differs from the GPU centre rule:
  - report's `floor` model: 19..100%, per size 25% (32 x 48) to 73% (3 x 3), which is the report's "25-72%";
  - hardware rule: 0..100%, mean 34%; per size 74% (3 x 3), 47% (12 x 19), 32% (22 x 33), 21% (28 x 43), 11% (32 x 37), 0% (32 x 48 of a 72-row image: exact 3:2 ratio on both axes), 4..15% from 35 px wide up.
- So the claim "25-72%, cannot be the oracle" is true for the wrong model; against the real PS1 rule the flights are exact at rest and differ by 4..16% of the pixels on the large quads and by 40..100% on the small ones. The conclusion (GPU cannot be the PS1 oracle on flights) stands; the numbers, the `*_psx.png` references of `out/` (they are built with the superseded rule) and the ADR sentence must be redone with the verified rule.
- "Consistent with D-E19-92" is overstated: D-E19-92 (and D-E19-97) are about entity and effect quads, and promise **exact at x1** (the G2b `DrawPsxQuad` rule). A portrait flight drawn by an MGUI `Image` is not exact at x1. The ADR must say it is a new, explicitly accepted deviation, or the author must be asked.
- Possible way to be exact at x1 with the existing bindable translation, **untested**: translate the quad by tx = 0.5 * (1 - w / 48) (and ty = 0.5 * (1 - h / H)) in PS pixels on top of the integer position. The GPU sample is then `floor((i + 0.5 - tx) * s / d)` = `floor(i * s / d + 0.5)` algebraically, and for 0 < tx < 0.5 the pixel-centre coverage of the quad at x1 is unchanged. Needs a GPU probe (MGUI may snap transformed rectangles; float ties; at k > 1 coverage shifts by up to k * tx screen pixels).

### B2. Minor
- The cell helper is `SetSprt` (code `0x64` + the w/h words), not `SetSprt8`; the semantics in the report are right.
- The report's "the flight reads as a bright flash for about 0.2 s of the 0.3 s": my estimate gives a visible (>= 8/255) change on 76..96% of the opaque texels on 13 of the 14 non-degenerate passes of the opening (all but the 44 x 52 one), so the report's figure is if anything conservative; same conclusion.

## C. Missed items with plan impact

1. **Cursor in `Apply(box, speakerDrawn)`** (impact: spec + test). The shipped `Apply` returns early when the box is not drawn, so the cursor keeps its last `Visible`. The report names `Visibility` bindings for `Frame` and `TextClip` only; the satellite-only pass must also collapse `Cursor` (its probe view model does, `Program.cs:281-283`). Put it in the plan text and in the S5 N+40 test.
2. **Bank 15 (Bonaire) portrait is not in `UI/Portraits`** (impact: tests/assets). Its sprite is `Entities/Bonaire (...)/sprite_61779896438529.sprite`; `UI/Portraits` also holds the hero's inventory sprite. A GPU test or a census that enumerates the folder gets 24 dialogue portraits + 1 foreign one and misses Bonaire. Enumerate by id from `portraits_table.tsv` / `sprite-records.json`.
3. **"No preload" rests on the two small sheets** (impact: risk). Measured: map 6 (512 x 238) and map 17 (512 x 328), 3.5..5 ms. The dialogue sheets go up to 512 x 1188 (map 327 Melzas, ~3.6x the pixels), 512 x 643 (map 321), 512 x 554 (map 10, 6 portraits): extrapolated 10..18 ms, i.e. up to one 20 ms tick. Measure map 327 and 10 in the f4c tests before keeping "none needed"; the fallback (`Resources.TryGetTexture` at map entry) is cheap.
4. **Reference set size and content** (impact: annex). `out/ref` = 146 PNG, 1.2 MB, vs the 124 KB precedent of f2b1; it includes `*_psx.png` built on the superseded rule: drop them or rebuild on the verified rule (B1). 180 name images could be composed by a small C# reference (like `AlundraTextBoxPixelTests.Compose`) instead of being committed.
5. **Binding release** (impact: low). `AlundraScreenBindingReleaseTests` covers only the inventory and HUD screens; the text-box screen gets two more bound render-transform properties and nested view models. Adding it to that class is a one-test addition (the screen's `Dispose` is already tested elsewhere).
6. **Union rule and leftover portraits** (impact: low, behaviour note). With `any = box.Drawn || NameBox.Drawn != null || Portrait.DrawnThisStep` a portrait left at rest by an attempt whose box never opens keeps the modal screen pushed until `NotifyPresenterClosed` or a map entry. This is the binary's behaviour (portrait state stays 4) and the director resets it at map entry, so it is acceptable, but it deserves one sentence and a test (portrait started, no box, map entry -> screen removed).
