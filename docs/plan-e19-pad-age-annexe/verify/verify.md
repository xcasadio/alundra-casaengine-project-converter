## 2. Refuted or imprecise

1. **Line endings ("LF in ... the plan")**: `docs/plan-e19-opcodes.md` is CRLF in the working tree (10963 CR = 10963 LF, byte count by `tr`; the report's own copy too). LF files: `AlundraSaveBookEndToEndTests.cs`, ADR-0040, `docs/plan-e19-save-order-annexe/notes.md` and `verify.md`. CRLF: proxy, director, `AlundraSaveScreenTickOrderTests.cs`, `docs/decisions/README.md`, the plan, `docs/plan-e19-f3-annexe/census-notes.md`. (`git ls-files --eol`: all `i/lf`, `core.autocrlf=true`, so git hides it; an executor that inserts the new plan section with LF newlines leaves a mixed file in the working tree. Use a byte-safe edit per file; do not trust `grep -c $'\r$'` under MSYS, it counted every line as CR.)
2. **Adjacent observation, trigger description**: "the inventory TRIGGER `0x80055570` (Start held, `0x800555B8`) runs in `Update(0)` after the sampler (age 0)" is imprecise. `0x80055570` has TWO call sites: `0x8002BCEC` in `Update(0)` (guard: pressed word `& 0x803`, not Select-held, memory-card state 0) and `0x800481D4` at the TAIL OF THE DISPATCHER (deferred request `[0x80153194] == 2` with slot 4 inactive), i.e. also in `RenderScene`, age 1. And `0x800555B8` tests the held word's direction bits (`0x2000`, `0x8000`, `0x1000`, `0x4000`) before falling to `0x80055624` (opens slot 6), it does not test Start. The slot-6 per-frame update `0x80056598` (installed at `0x80055554-0x80055564`) and slot 4 (`0x80053328`, sub-inventory: 6 interval reads `0x8005354C-0x80053658`) do read in `RenderScene` (age 1). So the gap is real for the inventory AND the sub-inventory, but the trigger cannot be summarised as "age 0".
