## 2. The refuted claim: the 0x44 marker IS cleared

The handler `0x8003E88C` keeps its marker in the program state at `+8` (`a3`), compares it with `pc` (`0x8003E8AC-0x8003E8B8`) and stores `pc` there on first entry. The report only drove the handler directly, never the interpreter loop. The loop (function `0x8004205C`, fetch at `0x80042280`, handler called at `0x800422F4` with `a3 = s3` = the same state) does, right after the handler returns:

```
80042324  beqz $a0, 0x80042344      ; 0 = yield: marker kept (0x44 first entry and every poll while the word is 0)
8004232c  sw   $zero, 8($s3)        ; non-zero return: marker := 0
80042330..8004233c  pc += a0 ; j 0x80042280   ; same tick
```
(and `0x800421F4` does the same for opcode 0). So when 0x44 completes (word 1 or 2, handler returns 1) the marker is zeroed. A later visit of the same pc (retry loop) has `marker (0) != pc` and takes the FIRST-ENTRY path again: it zeroes the word, opens a new choice. There is no stale re-poll and no original defect to fix. Question 3 of the report (fix the stale marker per the 2026-09-25 rule) is moot; nothing to preserve and nothing to correct; the port just needs "a 0x44 re-executed asks again", which is what a plain re-entrant opcode does.
[hyp] only residual: a script abandoned while the choice is open leaves marker = pc and the slot active; not exercised.

## 3. My own comparison model vs real code (`cmp.py`)

I ran the report's `ChoiceBox` + `PadWords` (imported from its `model/choice_model.py`) side by side with my interpreter running the real code, 300 random pad sequences of 120 frames (random held words incl. Compared every frame: active flag, update-function state (init/in/active/out), cfg.x, selection, counter, the caller's result word, the sounds. Result: 300 cases, 0 mismatching, 290 resolved to the end. Sensitivity: mutating the model's counter wrap to 39 is caught in 114/120 cases; mutating the repeat delay to 19 is caught in only 2/120 random cases (random pads rarely hold a key), so the repeat timing is verified by the targeted runs of section 1 row 3b, not by the random run.

## 4. Corrections to the report

1. Claim 9 (and notes section 5 last bullet, section 9, question 3 of section 11): remove; replace by "the interpreter zeroes the marker on completion (0x8004232C); a re-visit asks again".
2. Section 1.2 row 8 / section 10 item 4: the debug preset is not "possibly reachable": its gate `[0x800AF2B0]` is cleared only when the read-only word `[0x8009A858]` (0 in the image, never stored) is non-zero. Treat as unreachable in retail.

4. Strengthen section 3: for Left/Right the by-interval word gives "press edge + repeat from the 21st pass"; because a held direction pressed during the slide-in only takes effect when the repeat arrives (pass P+21), a direction pressed at N+6 and held acts at N+27 although no edge happens in the active window. The report's V4 only covers a direction pressed inside the window.
5. Font table address: `0x800993C4` (not `0x800A93C4`) if anyone re-derives the widths.

## 5. Missed or sharpened points relevant to the plan

- The text box's own button is Square (0x80); the choice uses Cross only. A port must not route Cross to the text box while a choice is open, and Square must keep working for the text box underneath (it is not read by the choice). This closes the "pad coupling" question the report left open.
- The retail game has no cancel on this box: "validation with Cross" in the sketch is complete; no Circle/Triangle/Start handling to add. The engine's mouse picking has no binary counterpart.
- Result consumers all see the answer in frame C+18 because the callback runs inside RenderScene before Update(0): 0x44 (script phase), the save book (entity update, state 4 polls `0x80191260`) and the file menu (slot 10 runs after slot 3 in the ascending dispatcher loop `0x8004813C-0x80048174`).
- Caller 5 (0x8005FC68) does not preset its result word `0x800C4988` before the opener at that site (I did not trace the earlier writes); the variant caller 7 presets it to 2 at `0x8005F9B0`. Only relevant if f3 ever ports the memory-card prompts.
