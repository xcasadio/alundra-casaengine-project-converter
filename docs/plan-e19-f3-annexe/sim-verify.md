## 2. What the report did not say, and what I found

1. **No test covers "director present, no presenter" for 0x44.** The runner's degraded exit `choiceDirector == null || !choiceDirector.HasPresenter` (`AlundraEventProgramRunner.cs`, `Result = 1` at once; `case 0x44` `:950`, gate `:961`, `OpenChoice` `:977` at `21fee93` = the annex's citation; `:962`, `:973`, `:989` at HEAD) is
   hit by only 2 tests in the suite, both with NO director at all. If the plan redefines `HasPresenter` (the report's open point 3), no test would notice a behaviour change of the presenter-less
   branch: add one before touching it. Also: with the faithful box nothing in the choice needs an engine presenter, but the same `HasPresenter` gate still guards the book (`AlundraSaveBook.cs:235,272`)
   and the screen (`AlundraSaveScreenDirector.cs:984`), so [hyp, not run] removing the gate would turn a presenter-less run of a 0x44 into a real 37-tick wait that nobody answers instead of the immediate `Result = 1` (a hang in a test or arc that has no presenter).
2. **The 44 red depends on two design choices the report states but a reader may take for a fact of the binary**: (a) the hook becomes pad-driven (a hook that wrote the result word at once would keep
   most of the 36 non-engine-window tests green); (b) the engine window disappears (the 8 engine-window tests). Both are plan decisions, not consequences of the binary.
3. **Pad reaches the choice while a box is up**: `LastPadState` is sampled by the player's `Update` outside the gameplay gate (`AlundraEntityScriptProxy.cs:1196-1206`, "dehors"), and the proxy's pad loop
   is never gated (`AlundraWorldProxy.cs:2104-2106`), so the choice pass sees Cross/Left/Right during `MessageBox`. The report's hook bypasses `LastPadState` (it injects words), so no test proves the whole
   path hero controller -> `BuildPadState` -> `TickPad` -> choice; the report says so (section 6, limits). I agree: UNCONFIRMED end to end, plausible by the code above. The same path already carries the text box's
   Square and the save screen's Cross/Down (validated in play per the memory notes).
4. **The "14/14" wording**: say "13/14 in the first full run, the opener-sound mutant after strengthening the comparison, 14/14 in a single rerun" (I reran it, section 1 row 7).
5. **Line numbers of the runner** moved by `3940630` (new cases 0x20/0x22/0x23): `case 0x44` 950 -> 962, gate 961 -> 973, `OpenChoice` call 977 -> 989; the annex cites `:977`. Test line numbers did not move.
6. The orders A and B only matter for LATE answers (+1 in B): confirmed, and explained by the binary: the screen's opener at S gets its first slot-3 pass at S+1 in the binary and at S in the DLL
   (screen ticks first), the consumer reads one pass later in the DLL: both give 37 for an on-time answer.
7. Not rechecked by me (no change to the report's own status): pixels and the choice view (out of scope of the sim); a run through a real `AlundraPlayerController`; the hypothesis that the hero cannot jump
   during a choice (`ControlLocked`/`MessageBox` are set by every mode-1 open: `AlundraGameState.InputBlockedMask` = ControlLocked | MessageBox | ForcedSequence, and the 0x44 sites keep the box up until the 0x51).
