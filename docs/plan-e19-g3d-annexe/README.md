# E19.g G3d annex (native effect creators and the life vessel `0x82 0x53`)

Plan: `docs/plan-e19-opcodes.md`, section "E19.g G3d".

## `discovery/` (read-only discovery of 2026-10-06, night, and its counter-check)

- `discovery/notes.md`: the binary path of `0x82 0x53` (`0x8003FE7C` -> `0x80034108` -> `0x800333AC`), where the hero's life lives
  (O-E19-39), the DLL today, rules G3D-R1 to G3D-R4, values, closed file list proposal, risks.
- `discovery/lib/g3d-golden.tsv` (generated by `g3d_golden.py`, `--check` replays it; rows `V`, `S`, `T`, `F`, `P`) and
  `discovery/lib/g3d-modes13.tsv` (generated by `g3d_modes13.py`): values produced by the real code in the MIPS interpreter.
  `rules_check.py` is a pure Python model of the rules (0 mismatch).
- `discovery/data/sites53.out`: the 8 `82 53` sites (map, program, pc).
- `discovery/verify/verify.md`: the fresh counter-check (translated from French). **Where it disagrees with `notes.md`, the
  counter-check wins:**
  - "identical at one tick per frame" is too strong: the DLL draws the random numbers when the queue is applied (`RunFrame`), after
    every draw made by the scripts of the same frame; the binary draws at the script's position. The order differs as soon as another
    script draws in the same frame (none of the five maps has an `0x0C` or `0x8C` instruction; random walk modes were not scanned).
  - the seed assertion must be `(uint)AlundraRandom.RandomSeed` (the state is an unmasked `ulong`).
  - `0x800333AC` has three callers: the script path and two native chest / pickup paths (`0x80033E70`, `0x80034080`, from the overlay
    function `0x8007C174`): 39 treasure chests with `Contents == 0x53` and the `I83` vessel entities. The script sites are the minority
    of vessels; chests and pickups come with E14. The pure function must take the hero position as a parameter.
  - the modes 1 and 3 creators (G3D-R4) are part of D-E19-96's "native creator interface", not optional.
  - variant A (stats written by the setters) is a provisional seam: porting the end-of-`MovePlayer` synchronisation requires moving
    to the entity-borne life (variant B) at the same time.
  - no test save reaches maps 134, 258, 298, 302 or 398.
- The scripts read the game binary and `DATAS.BIN` through absolute paths of the session scratchpad and of the author's machine
  (`lib.py`, `fxm.py`, `fixpaths.py` was not kept): adapt the paths before running them. The large working files (`ins.pkl`,
  `fx_all.json`, `names.json`) were not versioned; `idx.py` and `fxm.py` rebuild them.
