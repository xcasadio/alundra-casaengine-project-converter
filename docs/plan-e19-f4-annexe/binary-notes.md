## 1. Opening (the tick of the opcode)

- `0x0D` `0x8003D578(a0 = entity, a2 = &pc)`: `if entity[0x6C] & 0x800000` portrait opener `0x80057C84(&e+0x114, &e+0x118, &e+0x11C, &camX 0x800E4328, &camY 0x800E432C, u, v, w, h, clut, tpage)`;
  then `0x80059F6C(entity[0x68])`; then `TryOpenDialog(op[1], op[2])`; returns 3 if it opened, else 0 (retry next tick). **[bin]**
- `0x5C` `0x8003F01C`: count = `0x8003C954(entity, op[1])`; `0x8013D8D8` = `[0]`; if count != 0: same portrait + `0x80059F6C([0][0x68])`; then `TryOpenDialog(op[2], op[3])`; returns 4 / 0. **[bin]**
- `0xC4` `0x80041DA8`: count != 0 gates BOTH: portrait of `[0]` (same code, from the frame record, NOT from the script operands as the decompilation shows), name `= op[2] | op[3] << 8`; `TryOpenDialog(op[4], op[5])`; returns 6 / 0. **[bin]** (decompilation `EntityEventHandlers.cs:3694-3720` passes operands 4-7 as the portrait rectangle: wrong, the binary decides.)
- `TryOpenDialog` -> 0 while `g_dialog_flags & 4`; `InitializeDialogMessage 0x800450F0` clears the shared staging buffer `0x80149CE8` (`bzero 0x800`, `0x80045564`) AFTER the name open already used it: no residue in the normal flow. **[bin]**
- Frame order (validated): text-box pass (slot 0, may trigger the close) -> choice (slot 3) -> name pass (slot 12) -> OT build with the portrait pass -> script phase. All positions read for the portrait are those at the HEAD of the frame (close) or at the opcode (open): `entity +0x116/+0x11A/+0x11E` (integer halfwords of the 16.16 PosX/PosY/PosZ) and the camera words. **[bin]**
- Opening gate details: the portrait ignores an open while state != 0 (`0x80057D30`), the name ignores while `flags & 4` (flags 5, 4 AND 6 count as open). A name left closing (6) is NOT reopened by a retry until it is released (T+17).

## 2. Name box, to the tick

Block `G2 = 0x80180240`: `+0` flags (1 sliding in, 2 closing, 4 open), `+4` slide block `S2` (tick, steps 15, mode 2, start x/y at `+0xC/+0xE`, end `+0x10/+0x12`, origin `+0x18/+0x1A`), `+0x20/+0x34` the two SPRT prims (db 0/1), `+0x48` id. Slot 12 entry `{cfg 0x800A58BC, +8 = 16, +0xA = 8, +0xC = 32, +0xE = 4, init 0x8005A268, update 0x8005A3E0, layer 5}`.

- **Init `0x8005A268`** (inside `OpenSlot`): mode 2, tick 0, steps 15, start (320, cfg.y), end (cfg.x, cfg.y), origin (cfg.x, cfg.y), flags = 5, text prep `0x800472D0(prims, ETC[id], 6, 0, y = slot[+0xA] + cfg.y = 148, 3)` (bzero staging, render the string into VRAM band 3 at (960, 336), two SPRTs 255 x 16, u 0, v 0x50, palette #8). cfg.x is NOT written by the init: the first move is the first pass (N+1). **[bin] [emu]**
- **Update `0x8005A3E0`** each frame while slot flag 1: if `flags & 3`: `UpdateUiBoxesPosition(cfg, S2)`; on its return 1 (18th call): clear bit 0; if bit 1: restore cfg to the origin, `CloseSlot`, flags 0, return 0 WITHOUT drawing. Else draw: text SPRT x = cfg.x + trunc((112 - CalcTextWidth)/2), y = 148 (the SPRT of the current display buffer), linked into OT slot 6, then a `DR_AREA` clip (cfg.x + 16, 148, 258, 34) (x clamped to 320, width clamped to 320 - x) linked in front of it. The frame cells are moved by `UpdateUiBoxesPosition` and chained into slot 5 by `0x800481F8`. **[bin] [emu]**
- **Close `0x80059FE0`**: `if flags & 4: flags = 6`; the slide block is rewritten UNCONDITIONALLY: tick 0, steps 15, mode 2, start = current cfg.x, end x 320 (a close during the slide-in starts from where the box is; a second close restarts the slide from the current x). **[bin] [emu]**
- Table (cfg.x per pass; frame cells at (cfg.x, 140), text x = cfg.x + trunc((112 - w)/2)): see Summary 6; example Jess (w 21): text x 365 348 331 314 297 280 263 246 229 212 195 178 161 144 127 109, rest 109. Widths/rest x of the 60 names: `names_widths.json` (min rest x 92, none clipped).
- Only the left of the clip could cut and it never does: **the clip is moot for the real names** (a plain screen-edge clip is enough).

## 3. Portrait, to the tick

Block `G = 0x80180070`: `+0` state (hw: 5 = flying in then settling, 4 rest, 2 flying back, 0 off), `+4` two POLY_FT4 (0x28 each, per display buffer), `+0x54/+0x58/+0x5C/+0x60/+0x64` pointers (entity X, Y, Z blocks, camera X, camera Y) captured at open, `+0x68/+0x6C` start, `+0x70/+0x74` destination, `+0x78/+0x7C` span, `+0x80` counter, `+0x84/+0x88` size (48, 56 constants), `+0x8C/+0x90` rest (set by the wrapper).

- **Open core `0x80057CF0`**: returns at once if state != 0. Else: both prims: `SetPolyFT4` (code 0x2C), rgb 255, u/v rectangle from the frame record (u, v, w, h), clut, tpage; positions; head point `sx = e.x16 - camX`, `sy = e.y16 - camY - e.z16 - 0x20`; `G[0x70/0x74] = rest`, span = head - rest, counter 15, state 5. **[bin] [emu]**
- **Pass `0x80057EBC`** (from `0x80058134`, OT slot 3, once per frame while state != 0), counter c:
  - c > 0, bit 0 (in): x = restX + trunc(dx·c/15), y = restY + trunc(dy·c/15); w = trunc(48·(15-c)/15), h = trunc(56·(15-c)/15); rgb = 127 + trunc(128·c/15); c -= 1.
  - c > 0, bit 1 (back): x = ex + trunc(dx'·c/15) with ex = entity head NOW, dx' = restX - ex; w = trunc(48·c/15), h = trunc(56·c/15); rgb = 127 + trunc(128·(15-c)/15); c -= 1.
  - c = 0, bit 1: state 0; drawn once more at (8,116), size 0 x 0, rgb 0 (degenerate: invisible). c = 0 otherwise: state &= ~1 (5 -> 4), (8,116), 48 x 56, rgb 128 (every frame while it stays).
  - passes: N+1 .. N+15 flying (c = 15 .. 1; first one 0 x 0), N+16 and on rest. Return: T .. T+14 flying (T at the rest position, rgb 127, full size), T+15 degenerate, gone at T+16. **[emu] model**
- **Close `0x80057B84`**: if state != 0: destination := entity's screen head point NOW, start := rest, span := rest - head, state 2, counter 15. Called at the text-box close trigger (also by the inventory exits). Restarts if called twice. **[bin] [emu]**
- Prim: code 0x2C = **modulated, opaque** (no semi-transparency whatever the image carries), all three rgb equal. Modulation factor k = rgb / 128: opening 1.99 -> 1.05, rest 1.0, return 0.99 -> 1.92; PSX modulation saturates at 255 (overbright, whitening). The only ramp is this one (vertex colour, one value for the three channels). **[bin]**
- Size per portrait: the TEXTURE rectangle is the frame record's w x h (48 x 56, or 48 x 72 for indices 122 and 162); the QUAD is always 48 x 56 at rest (hard-coded `0x80057E4C/0x80057E54`): the 48 x 72 images are squashed (confirmed on the real prim: uv rectangle 48 x 72, quad 48 x 56). Bottom of the quad at rest = 172 for every portrait; top = 116. For D-E19-49 (show 48 x 72 whole, bottom aligned) the rest top would be 100 (derived choice, not binary; the flight formulas generalise with h = 72: sizes (0,0) (3,4) (6,9) (9,14) (12,19) (16,24) (19,28) (22,33) (25,38) (28,43) (32,48) (35,52) (38,57) (41,62) (44,67)).
- Which portrait for which speaker: the speaker's OWN sprite record, first image, palette `frame[3]&0x3f + entity palette base` (0 for map sprites). The extractor already exports it (`DialoguePortrait`, 331 records, atlas regions non-empty: checked on map 17 record 122, 2395 of 3456 texels opaque); the converter does not read it yet (`rg DialoguePortrait` finds the analyser only).

## 4. Interplay with the text box and the choice box (frame numbers, text "AB", Square pressed every frame, `values.md`)

- Open (S1): text box first pass N+1 (y 240), name and portrait first pass N+1; all three at rest at N+16 (text y 168 from N+16, name cfg.x 64 from N+16, portrait (8,116) 128 from N+16); first glyph N+19.
- Close (S1): trigger T = N+22 (`close-trigger`): name pass T at 64 (flags 6), portrait pass T at rest rgb 127; name released T+17 (N+39); portrait degenerate T+15, gone T+16; text box released T+18 (N+40, `DialogClosed`, `0x39` hands over).
- No name / no portrait (S2, S3, S4): the other element and the text box are unchanged (the text box timeline of f2a is untouched).
- Retry-ahead (S5, two `0x0D` in a row, no `0x39`): the second opcode retries every tick from N+1; its name opens at N+39 (the tick the first name is released; first pass N+40, the text box of the 2nd opens at N+40, first pass N+41), its portrait at N+37 (the tick of the first portrait's last pass; first pass N+38, **visible 3 x 3 / 6 x 7 while the first text box is still sliding out and gone**). The model and the real handlers agree on every frame.
- The choice box (f3) does not touch the name or the portrait; geometry: the name frame (x 64..175) is directly left of the choice frame (x 176..303); the name text clip contains the choice labels (their draw area is the name's while the name box is open, harmless). Name frame, choice frame and choice cursor are in slot 5, name text and choice labels in slot 6, so name text is above the choice frame/cursor (never overlapping at rest).
- **Independent lifetimes**: the name box and the portrait can START before the text box exists (retry) and always END before it is released (T+15 / T+17 < T+18): a modal text screen pushed at `Open` and removed at the release cannot carry them faithfully in the retry case (they would need their own screen/presenter, or the text screen pushed from the first attempt).

## 6. Not proven / hazards

1. **GPU pixel sampling of a scaled quad** (the flight draws a W x H texture on a smaller quad): nearest-texel selection of the PSX rasteriser is not modelled; the rest state is 1:1 (48 x 56) for 324 of 331 records.
2. **OT slots >= 7**: the name's `DR_AREA` (slot 6) is never reset in the same frame; I found no prim of the UI OT in slots 7..9 (a false lead at `0x80057278` was a `+0x10` offset), not proven absent.
3. **Staging-buffer hazard** (original defect, not planned): the name opener `bzero`s and fills the shared 2 KB staging `0x80149CE8`; if it runs while ANOTHER text is typing (retry of a named dialogue behind an unnamed one, no `0x39`) the typed line is wiped / overlaid by the name pixels. Corpus occurrence not measured (needs speaker names per site); per the 2026-09-25 rule an original defect is not reproduced.
4. Wrappers overwrite the shared rest position `G[0x8C/0x90]` even when the open is ignored; a dialogue start during an inventory portrait would move the inventory's return target. Unreachable in play (inventory locks control), not modelled.
5. The portrait close dereferences the speaker's slot at close time (pointers kept from the open): a destroyed/recycled speaker slot (ADR-0024) reads whatever the slot holds. Not modelled.
6. `0x80081AA4` (Krom2RawAdd) is stubbed to "not kanji": real names are ASCII.
7. Boot-only reset of the blocks: `0x8005A0C8` / `0x80057B64` are called from the UI init `0x80044BE4` (single caller `0x8002C238`, boot); no map change or warp touches the name or portrait flags in the binary (only the inventory exits touch the portrait). A save load must reset both in the DLL (as `AlundraInventoryPortrait.ResetSessionForLoad` does).

## 7. What the plan needs from this surface

- **Rules** (all validated): Summary 1-13 and sections 1-4; the DLL structure they imply: (a) at EACH attempt of `0x0D`/`0x5C`/`0xC4` run `portrait.TryOpen(speaker)` (HasPortrait = `Flags & 0x800000`), then `name.TryOpen(id)` (id = `SpriteType` of the speaker, or the `0xC4` operand; only when the search matched for 0x5C/0xC4), THEN the existing retry gate; (b) the name and portrait passes run after the text-box pass of the same tick and before any script (position read at that point for the return flight, at the opcode for the start); (c) close both in the text-box close trigger (same tick as sfx 7); (d) a shared single portrait block for dialogue and inventory with rest position (8,116) / (248,104); (e) a name needs no clip.
- **Values writable in advance**: `values.json` (7 scenarios per frame, from the validated model), `names_widths.json` (60 names: width, rest x), the closed forms of Summary 6 and 9, the portrait census (`census_portraits.json`: map, sprite index, sheet, palette, source rect, size). A C# oracle can be a port of `model/f4_model.py` (about 150 lines, same shape as the f3 `choice_model.py`), compared to the DLL on the same random sequences as `validate.py` (mode "raw": open/close at random frames; mode "dialogue": driven by the text-box oracle).
- **Export changes**: (1) converter: read `SpriteRecord.DialoguePortrait` (already in `map_<n>.json`, atlas regions already filled: 331 records) and emit one `.sprite` per (map, sprite index) under `UI/Portraits/` plus an index keyed by (map, `SpriteType & 0xFF`) like `Data/inventory-portrait.json` (ADR-0005 precedent); the 7 images of 48 x 72 must keep their height; the portrait must not inherit the PSX semi-transparency mode that ADR-0033 puts on entity sprite quads (the binary's prim is opaque). (2) Name strings: nothing to export (`Etc.yarn` `Etc_0256..0511` already there, 60 non-empty); the DLL needs the `CalcTextWidth` advance table (f2b0/ADR-0036 `FontGlyphTable.csv`, already published). (3) Name frame sprite: exists (`g_textTilesConfiguration` `91ca17ae-...`, 112 x 32, f1).
- **MGUI / engine gaps to report**: (G-a) overbright modulation: the vertex colour ramp reaches k = 255/128 = 1.99 (saturating); MGUI elements only multiply by a colour <= 1 (`BlendType.Additive` exists only in `MGUI.Shared` `DrawSettings`, `rg BlendType` finds no element property in `MGUI.Core`); an exact rendering would be the image drawn twice, the second additive with colour (k - 1); precedent: the inventory portrait shipped with a normal tint (author's D2, `AlundraInventoryPortrait` summary). (G-b) growing quad from 0 x 0 with point sampling: `RenderTransform.Scale/Translation` (MGUI ADR-0020) is what the inventory used; a 0 x 0 pass must draw nothing. (G-c) independent lifetimes/z-order across screens (portrait over the text frame, name frame over it, name text over the choice frame): see section 4 "Independent lifetimes".
- **Questions**: none genuinely open for the binary surface.
