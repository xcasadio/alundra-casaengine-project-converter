## 2. Corrections to make in the report

1. `notes.md` section 5 says the speaker head point is needed "each tick while anchored". The binary does not do that: the start and the return snapshot the position (`0x80057E08-0x80057E84`, `0x80057B9C-0x80057BF8`) and the per-tick
   step `0x80057EBC` only reads the stored `[0x68]/[0x6C]/[0x70..0x7C]` values; no load of the pointer slots `0x54..0x64` outside those two functions. The report body (section 8) is right: read at call time and at return.
2. Map-event programs (slot B) run with the HERO as owner and initial logic entity (`AlundraWorldProxy.RunMapEventsPass`, `mapEvent.Entity = player`, `player.LogicEntity = mapEvent.Entity ?? player`), not "the map-event entity". Same effect (no name, no portrait), but see 3.
3. The 565 map-event sites are not all "no speaker": a program containing `0x43` (retarget) exists for 107 of the 565 B-only `0x0D` sites (98+9), for 260 of the 565 B-only `0x5C` sites, and for 6 of the 31 `0xC4` sites. The corpus oracle for those must be dynamic (order of `0x42`/`0x43`).
   Checked by hand: map 432 pc 331 (`0xC4`, name Nava): `0x43 [rec 0]` at 273 then `0x42` at 289 resets to the hero, so the match is the hero: no portrait. Map 476 (Lars, 4 sites): retarget to record 1 = common sprite, no portrait. Map 226 pc 1132: the `0x43` (records 6 = Ronan, who HAS the portrait flag, and 10) come AFTER the `0xC4` in a tick program of record 10 (no name, no flag): a loop that keeps the retarget would show Ronan's portrait: "none opens a portrait" is CONFIRMED for 30 of 31 and UNCONFIRMED for this one site.
4. The `0x100` of `SpriteType` depends on the instance's `SpriteDirection & 0x80`; the "no ETC name 314" bucket of `0x0D` mixes 183 sites whose owner is a common sprite (bit clear: the index stays < 0x100, so refused) and 131 map-sprite owners without an ETC entry.
5. Line numbers: `SpriteType = 0` hero at `AlundraWorldProxy.cs:1641`, flags packing :1638.
6. The null test of the name opener is dead (see claim 7): say "empty string refuses".

## 3. Missed, with a plan impact

1. **Textures are loaded on demand from OTHER maps' sheets.** A portrait sprite sits in the sheet of its bank's canonical map: 13 distinct sheets (maps 6, 8, 10, 14, 17, 41, 134, 144, 162, 185, 308, 321, 327). `CasaUIAssetProvider.TryResolveImage` acquires the sprite data and its sheet texture synchronously the first time a name is bound and holds them until the provider is disposed; the first speaker of each sheet decodes a PNG (map 10: 512x554) on the main thread during the dialogue opening. The plan has to say: pre-resolve (at spawn or map entry for the banks present) or accept, and how headless tests get a texture.
2. **The first update of the name box leaves the frame at x = 320; before it `cfg.X` still holds 64.** `0x8005A268` (init) never writes `cfg.X`; only the first update (`0x80047DD0`, counter 0 = start position 320) does. Whether the frame can be drawn once at x = 64 depends on the callback order inside `RenderScene` (draw of the UI boxes vs the update callback). To pin on the binary surface (D-E19-81). The slide takes 15 + 2 + 1 update calls (18) in and out.
3. **Reset values**: the portrait reset `0x80057B64` writes rest (8, 0x78 = 120), the dialogue start writes (8, 0x74 = 116) before its `state == 0` guard (a busy block gets its rest overwritten, harmless because each start rewrites it); the DLL `ResetSessionForLoad` (inventory) should also clear a dialogue flight and the name box state (map entry, `AlundraSaveGame*` tests listed by the report).
4. Retry with another box open (`0x0D` of speaker B while a box is open): the name box and portrait of B DO open (guards `&4` / `state == 0`) and stay until the next close trigger: with the screen pushed because the other box is drawn, this is representable; visibility is tied to `box.Drawn`, which hides the first (0x0 / x = 320) pass anyway, so no visible offset.
5. The portrait colouring comes from entity palette words (`+0x1B0/+0x1B4`, `0x8003D5B8/D5E0`); the export has one RGBA image per bank. Safe today (same pixels across all maps, claim 16), but the oracle for a later palette-variant NPC would be wrong.
6. Search order: the binary takes element 0 = lowest entity-array index; `EntitySearchService` iterates `spawnedEntities` in the DLL's own order (same unless several entities share an `EntityRefId`): add a test with two matches.
