# ADR-0002: The game's screens are project assets bound to observable view models

- **Status**: Accepted
- **Date**: 2026-09-24
- **Source**: this chantier: `docs/plan-bound-screens.md`, branch `chantier/bound-screens`, the author's answers
  of 2026-09-22 to 2026-09-24. Supersedes [ADR-0001](0001-game-screens-embed-their-xaml-in-the-dll.md).
  Engine counterpart: CasaEngine ADR-0038; MGUI counterpart: MGUI ADR-0016.

## Context

- ADR-0001 embedded the game's XAML screens in `Alundra.dll`. Its stated consequence: such a screen cannot be
  opened as a `.uiscreen` from the editor's content browser. The author requires every screen of the game to
  be editable in the editor.
- `alundra-project/` is generated by the converter and ignored by git (`.gitignore:63`). An export never
  deletes a file it does not write, but it rewrites `AssetInfos.json` in full, so a hand-placed asset loses its
  catalogue entry at the next export. Git cannot re-include a path under an ignored directory with a single
  negated pattern (checked on 2026-09-23 with `git check-ignore -v`).
- The HUD is built in C# (`Alundra/Scripts/AlundraHudScreen.cs:68`, a 26-image pool created in `OnInitialize`).
  The inventory is XAML (`Alundra/Screens/InventoryScreen.xaml`, embedded, `Alundra/Alundra.csproj:23`) whose
  every `Image` is assigned by code. Both screens are driven by presenters that push a whole model every logic
  tick (`AlundraInventoryPresenter.cs:67-80`, `AlundraHudPresenter.cs:112-135`).
- Three images cycle over time, computed today from the 50 Hz logic tick: the inventory cursor (4 frames of
  10 ticks, `AlundraInventoryDirector.cs:520-524`), the HUD magic pips (4 frames of 10 ticks with a per-pip
  phase, `AlundraHudDirector.cs:461-468`) and the HUD coin (4 frames of 6 ticks, only while the money counter
  rolls, `AlundraHudDirector.cs:594-634`).
- The dialogue box is the engine's `DialogueScreen`, pushed by `AlundraDialoguePresenter`.

## Decision

- **Screens are project assets.** Each screen of the game is a `.uiscreen` envelope, its `.xaml` file and a
  design-time data file under `alundra-project/UI/Screens/`. That folder is versioned through a cascading
  exception in `.gitignore`; no converter writer writes there; the converter registers the screens it finds
  there in the catalogue with stable ids. The DLL loads them through the catalogue. No screen markup stays
  embedded in the DLL.
- **Screens bind to observable view models.** The presenters write view models that notify only the values
  that change; the markup binds image sources, visibility, texts and positions. Positions keep being computed
  from the original game's data by code, and reach the screen through bindings.
- **The HUD is XAML**, with a fixed list of named slots (26 tiles, 2 equipment backgrounds, 2 equipment icons),
  laid out in native pixels and scaled once like the inventory.
- **Cycling images are asset animations.** The converter writes the cursor, pip and coin cycles as `.anim2d`
  assets; the screens name them as image sources; the UI clock plays them. The per-pip phase is a start
  offset; the coin plays only while the money counter rolls and rests on its first frame otherwise, as in the
  original.
- **Timing.** UI screens (HUD, inventory, dialogues) no longer follow the 50 Hz logic tick. Each animation's
  frame changes stay within one logic tick (20 ms) of the original's, checked by tests.
- **Dialogue box.** The game ships its own dialogue screen asset, through the engine's replaceable dialogue
  screen (ADR-0038).

## Consequences

- Every screen opens, previews with sample data, and saves from the editor; its markup and design data are
  versioned with the rest of the repository.
- A change to a screen no longer needs a rebuild of the DLL, only a reload of the project.
- `Alundra.Tests` reads the screens from the versioned folder of the repository, not from an export.
- The presenters' tests move from asserting view-interface calls to asserting view-model properties.
- Driving the cycles by the UI clock rather than the logic tick can shift a frame change by up to one tick
  against the original; the author judged it invisible.
