# ADR-0075: The Alundra gameplay DLL is restructured: one folder, one namespace, no `Alundra` prefix in type names

- **Status**: Accepted
- **Date**: 2026-10-16
- **Source**: this chantier: `docs/plan-restructuration-dll.md`, sections 0 (D-R-1 to D-R-9, D-R-10 and D-R-11 for R0), 2 (tree and rules) and 5 (slice R1, revision 1); inventory of 2026-10-16 (scratchpad `dll-structure/report_inventory.md`, `report_couplings.md`); engine ADR-0075 (`CasaEngineMonogame/docs/decisions/0075-script-objects-by-full-name-from-the-gameplay-assembly.md`); the name table `tools/dll-structure/table.md` (generated)

## Context

- The gameplay DLL holds 132 tracked files: 129 `.cs` files under `Alundra/Scripts/`, all in the single namespace `Alundra.Scripts`, plus `Alundra/Plugin.cs` (namespace `Alundra`), `Alundra/InternalsVisibleTo.Tests.cs` and `Alundra/Alundra.csproj` (no `<Compile>` item). 220 top-level types, 148 of them prefixed `Alundra`; 42 files declare several types. 311 of the 329 test files and `tools/AlundraTestSaves/Program.cs` use `using Alundra.Scripts;`.
- The author asked (D-R-1) for a folder per domain, one namespace per folder, no `Alundra` prefix in type names, tests in the same tree, and no cutting of the very large files in this chantier.
- The engine created script objects (entity proxy, world proxy, player controller, game mode, screen view model) from a short class name looked up in the whole AppDomain, so moving or renaming a class changed what the data resolved. R0 (D-R-2 to D-R-5, D-R-9 to D-R-11; engine ADR-0075) made the engine resolve them by full name, in the gameplay assembly only, and rewrote the exported data with the current full names (`Alundra.Scripts.…`). That is the prerequisite of this decision.
- The exported data cite nine types by full name: `AlundraWorldProxy`, `AlundraEntityScriptProxy` (two files: partial class), `AlundraPlayerController`, and the six screen view models (`AlundraHudViewModel`, `AlundraInventoryViewModel`, `AlundraSubInventoryViewModel`, `AlundraTextBoxViewModel`, `AlundraChoiceViewModel`, `AlundraSaveScreenViewModel`).
- A check of the final names (`tools/dll-structure/check_names.py`, against the engine, MGUI, NvgSharp, the packages' XML documentation and the BCL reference pack) found that without the prefix four names collide (`PlayerController`, `MusicPlayer`, `Random`, `SoundBank`) and 143 are free. A namespace `Alundra.N` masks any imported type `N`, so some folder names are unusable (`World`, `Player`, `Camera`, `Dialogue`, `TextBox`, `Text`, `Debug`, `Math`, `Entity`). A type named `SaveScreen` inside a folder `SaveScreen` also clashes with its own namespace segment.

## Decision

- **D-R-1 (tree)**: a folder is a namespace `Alundra.<Domain>`, in English. The target tree is the one of section 2 of the plan: `Maps` (with `Loop`), `Session`, `Entities` (with `Spawning`), `Events`, `Ai` (with `Enemies`, `Projectiles`, `Objects`), `Hero`, `Combat`, `Items`, `Rng`, `Physics`, `Cells`, `Cameras`, `Rendering` (with `Backdrops`, `Effects`), `Audio`, `Transitions`, `Dialogues` (with `Yarn`), `UI` (with `Hud`, `Inventory`, `SubInventory`, `Messages`, `Choice`, `Speech`, **`Saving`**, `Shared`), `SaveGames`, `Probes`; `Plugin.cs` stays at the root, `InternalsVisibleTo.Tests.cs` becomes `Properties/InternalsVisibleTo.cs`. `Hero` and `Maps` replace `Player` and `World`. The folder of the save screens is `UI/Saving`, not `UI/SaveScreen`: the type `SaveScreen` lives there and a type must not carry the name of a segment of its own namespace.
- **Rules**: (1) a folder is a namespace; (2) no `Alundra` prefix in type names; (3) one main type per file, public secondary types in their own file (reading below); (4) a name exists once among the DLL, the engine, MGUI, MonoGame, the packages and the BCL, checked by script at every slice, and no type bears the name of a namespace segment of the DLL; (5) imposed renames: `AlundraPlayerController` -> `HeroController`, `AlundraMusicPlayer` -> `BgmPlayer`, `AlundraRandom` -> `GameRandom`, `AlundraSoundBank` -> `SfxBank`, `AlundraEventProgramRunner` -> `EventProgramRunner` (the interface file `EventProgramRunner.cs` becomes `IEventProgramRunner.cs`, its type `IEventProgramRunner`); (6) unchanged: the assembly name `Alundra`, the data keys (`AlundraCells`, `AlundraWallPlacements`, `AlundraFloorPlacements`, `AlundraCompanionJson`), asset names, the save format; (7) plans, ADRs and historical annexes are not rewritten.
- **Reading of rule (3)**: an entry of the tree is a file; "(+ X)" means X in the same file (`WorldProxy (+ MapEvent)`, `IEventProgramRunner (+ NoOp)`, `EntityScriptProxy (+ .HitPass)`). Rule (3) applies to every **public** secondary type that the tree does not keep with "(+ X)"; an **internal** secondary type stays in the file of its main type unless it has its own entry in the tree (`SlotShadow` in `Probes/`, `PortalScanner` in `Transitions/`). The main type of a file is the one that bears the file's name, except `EventProgramRunner.cs` (main type `IEventProgramRunner`).
- **Names**: the table `tools/dll-structure/table.md` (generated, with `table.json`, by `tools/dll-structure/gen_table.py` from the declarations of revision `5434cf6`, the end of R0) is the authority: for each of the 219 top-level types of `Alundra/Scripts` (148 renamed, 76 secondary types taking their own file, 205 files at arrival), its file, namespace and name after R2 (moved and split, no rename), after R3 (renamed) and finally. The same table gives the "old path -> new path" mapping for the frozen oracle annexes (D-R-6): their scripts are not corrected.
- **Order (D-R-5)**: two exports. R0 (done) rewrote the data with the current full names. R2 moves and splits, R3 renames, both leaving the nine data-cited types and the files that hold them in `Alundra/Scripts` (namespace `Alundra.Scripts`, current names); R4 moves and renames those nine together with a second export (converter, `*.design.json`, data). The partial `EntityScriptProxy` stays in its two files. Moves use `git mv`; renames use a refactoring tool, never a global text replacement (data keys carry the prefix without being types).
- **Checks**: `check_names.py --table` (no collision of a planned name, no segment masking a type, no type named like a segment) and `check_names.py --tree --stage r2|r3|final` (the tree against the table, every deviation listed) are the mechanical proof of R2, R3 and R4; `selftest.py` proves the checks fire. Each slice also runs the full `Alundra.Tests` suites in Release (neutralised copy) and Debug with no change of expected value, and a short author recipe in game.
- **Programme (D-R-8, D-R-7)**: `chantier/e20-heros` was merged into `main` first (fast-forward); the chantier runs on `chantier/restructuration-dll`, with no other slice (E20, E14, E19) in parallel.

## Consequences

- Easier: a type's namespace says where it lives; names are short; a duplicate name is caught by a script instead of a build error (`CS0104`) at the user's `using` list; the table lets the frozen annexes be read by path.
- Constrained: the nine data-cited types keep their current names and namespace until R4; the tests keep `using Alundra.Scripts;` until their types move; any file added to the DLL during the chantier must be in the table or `--tree` fails. A nested type of a test class may share a segment name (today `Session` in `Alundra.Tests/UI/TextBoxGpuHarness.cs`): the tool reports it as a warning, it masks the segment only inside its own class body.
- Deferred: the cutting of very large files (a separate chantier, D-R-1); the tests in the mirrored tree (R5); the living documentation and the `research/` scripts (R6).
- Limits: the declaration reader is a regular-expression reader, not a compiler; a package without XML documentation (`Portable.Xaml`) is not covered by the collision check and the build stays judge (`CS0104`). Rollback: `git revert` of a slice; for R0 and R4, revert of the parent commit and re-export from the previous commit.
- The engine side of the prerequisite (full-name resolution, the gameplay assembly only, the exception at load) is engine ADR-0075.
