## Method (independent of the discovery's probe)
- **Renderer**: my own C# console `src/Program.cs` (written from the public API, no copy of the discovery's probe): hidden `Game`, a `Host`
  (IRenderHost + IRawInputSource), my own stand-in `IUIAssetProvider`, `CasaMonoGameBackendBootstrap.Create` -> `CasaDesktopRuntime`,
  `new MGDesktop(runtime)`, `FontStashSharpTextEngine` + `StaticSpriteFont.FromBMFont`, my own XAML loaded through `UIScreenLoader`, my own
  view model (plan R2 formulas), `desktop.Update()` / `desktop.Draw()` into a `RenderTarget2D`, full target saved as PNG. **It contains no
  reference compositor.**
- **Reference**: `src/ref.py` (Python, PIL + numpy), written from the exported PNGs, `font3.fnt`, `glyph_table.txt` and the binary rules of the
  plan (frame (16,Y), cursor (288,Y+32), rows (x, Y+5+16i-scroll), band 255 x 16, clip (32,clipTop,258,clipH), frame+cursor then clipped text; BMFont
  pen/offset rule). The annex `.fnt` is rewritten by my own code from `glyph_table.txt` + `font3-charset.json`. `src/scen.py` = scenario table,
  runner and comparer (`out/last_run.txt`: 108 checks, 92 OK, 16 DIFF; every DIFF is an intended negative control or the LF/CR finding, see below).
- Extra: `xtest_3.8.4.1/`, `xtest_3.8.5.1/` (vstest host reproducing Alundra.Tests' pin), `vt_root/` (copy of the Alundra.Tests bin), `src/meas.py`, `src/sens.py`.

## Corrections to the report
1. **G6 wording** (item 12): `Desktop.Draw` is called in many `MGUI.Tests` (no-op or headless transactions). Say "no test draws an `MGDesktop` on a real device and reads pixels".
2. **Name lookup** (item 8): the last-writer happens to be the sprite given the catalogue order, so a name binding of the frame would work today by luck; the GUID remains the right choice.
3. **`ClipToBounds="True"`** (item 6) is redundant (default true); with `False` the clip disappears (476 texels). `LinePadding="0"` and `VerticalContentAlignment="Top"` are not needed for exactness (0 texels without), only `Padding="0"`, `WrapText="False"`, `Width="255"` are.
4. **Layout facts to keep**: `Padding="0"` on a TextBlock makes its height 16 (18 with the default padding); a 40-W row without `WrapText="False"` becomes 32 high (34 with default `LinePadding`).
5. The existing GPU test file is `Alundra.Tests/AlundraFont3GlyphTests.cs` (the earlier text implied `UI/`).

## Missed, or worth recording in the plan
1. **U+000A and U+000D are line breaks in `MGTextBlock`** even with `AllowsInlineFormatting="False"` (A+LF+BCD: 1400 texels differ at x2, first at (88,350); the row is 2 lines high). U+0000, U+0009, U+000B, U+000C, U+001B, U+001C, U+001F, U+007F draw as the font's glyphs (0 texels) (M_ctrl_*). Low risk: the DLL box turns newlines into tokens (`DialogueTokenKind.NewLine`), so a row string never holds them, but R2/T2 should state "a row never contains LF/CR".
2. **Auto-width of a font3 TextBlock = sum of `xadvance`**, for today's and the annex `.fnt` (e.g. "Bonjour, Alundra !" 105, 3-px last glyph rectangle: still 105; `meas.py`). This settles the earlier counter-check's C5 worry (`MeasureString` including the last glyph rectangle): it does not, so f2b0 changes no measured width, and `\H` widths from `font3.fnt` advances agree with what MGUI measures.
3. **Weak sensitivity of the text-over-cursor order**: the clip ends at x = 289 and the cursor starts at x = 288, so at most 3 texels overlap (x1) in real geometry; "K" x 60 at x = 39 with cursor `wind_201` gives 3 x k^2 overlapping texels (3 at x1, 27 at x3) and is exact at x1 and x3 (T_overlap_*). A T5 case that pins the z-order should use it.
4. **Modal flag and gameplay input** [hyp, code read only]: `PlayerInput.GetButtonState` gates on `IsInputEnable` and the mapping; the router's modal state only picks the receiving view (the player's own UI view is the modal view). I did not find a path where a modal screen blocks the pad; the current engine box is already modal in the same view. If the new screen stays pushed during the slide-out while today's engine screen is removed earlier, only `HasModalInput`'s duration changes. Not verified at runtime.
5. **First frame after a push draws nothing** (window not laid out before its first `Desktop.Update`), and every bound change lags one render frame (item 11): the box appears one frame after the binary's pass, uniformly (frame, clip, rows move together; only a changed cursor sprite shows early). Accepted for every Alundra screen today.
6. Test design: the GPU test can use a render target of any size independent of the hidden game's back buffer (mine: 1024x768 back buffer, targets from 320x240 to 960x720, `Viewport` offset); `RenderTarget2D` with `Depth24Stencil8` is needed for the clip (as the engine's own GPU test).
