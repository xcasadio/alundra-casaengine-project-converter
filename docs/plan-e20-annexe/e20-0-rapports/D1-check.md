### Important points the report missed

1. **The reference is not independent of the binary emulation.** The annex B.1 is itself titled "scénarios exécutés sur le vrai code" (`plan-e19-d2c-valeurs.md:58`). ADR-0023 line 9 says the E19.d2c discovery ran MovePlayer and the physics pass in two MIPS interpreters. So the PASS reproduces an earlier emulation of the same binary.
   - INFERENCE: if E19.d2c built its hero bank from the same decoded `map_alundra.json`, a bank-layout error common to both would cancel out. Its tools are not archived, so this cannot be checked.
2. **RNG:** both the plan and the oracle have the wrong state address (see the table). The real generator state was neither seeded nor reported, and the oracle corrupts sound-table row 48. The stubbed sound routine hides that corruption in D1, but D2 or later slices that run real sound or effect code would inherit it.
3. **Scratchpad stack switch** inside the tick is not modelled (see the table).
4. **Contract deviations:**
   - The tools sit in `docs/plan-e20-annexe/d1-oracle-moveplayer/tools/`, not in `docs/plan-e20-annexe/tools/` as `plan-e20-heros.md:394` asks.
   - `+0x1C4` is not set to `0x80127008` as the plan asks; tested above, it does not change S-A/S-B.
5. **Cosmetic:** in `S-B.machine.txt` the journal labels the warm-up ticks −60, −59, −58, while the trace labels them −3..−1.
