## The survivor

M10 recomputed the pivot from `keys[lo] + keys[hi]` at each pass of the loop. No test and none of the 130 vectors reached a case where a swap touching `lo` or `hi` changes the sum. A python model of the two variants (brute force over small squared distances) found the smallest differing worlds; the test `Q4_ThePivotIsFixedAtTheEntry_ItIsNotRecomputedAfterASwap` takes keys 4, 4, 1, 5 (slot 1 at (2, 0), slot 2 at (0, 2), slot 3 at (1, 0), slot 4 at (2, 1)): the entry pivot gives the slots `[3, 2, 1, 4]`, the recomputed one `[3, 1, 2, 4]`. Green on the real code (28 of 28), red on M10. Added in a separate commit (`7332cd95`). Not an equivalent mutant.
